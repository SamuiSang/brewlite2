🛡️ Task 3.1: Quyết định Kiến trúc Bảo mật (ADR-005)

Bản ADR-005 giải trình 3 quyết định kỹ thuật sống còn của phân hệ:

1. Băm mật khẩu bằng Bcrypt

Tại sao không dùng SHA-256? SHA-256 quá nhanh (hàng triệu hash/giây), hacker dùng GPU chạy từ điển giải mã được ngay.

Bcrypt (cost 10): Tự sinh muối 128-bit, tốn ~70ms cho 1 lần băm. Làm nản lòng hacker thử vét cạn và chống Timing Attack.

2. Stateless JWT (RFC 7519)

Tại sao không dùng Session RAM? Session bắt server nhớ trạng thái, khi mở rộng nhiều Docker container phải đồng bộ RAM rất phức tạp.

JWT (HS256, 24h): Token tự chứa dữ liệu (id, email, role). Server không cần lưu state, scale ngang vô hạn.

3. CORS Whitelist Chặt chẽ

Thiết lập tại main.ts, chỉ cho phép domain Next.js Frontend truy cập.

Chặn đứng nguy cơ các website độc hại gửi request ngầm trộm dữ liệu từ trình duyệt người dùng.

Đây là phần code Backend trực tiếp của bạn trong Sprint 1 trên nhánh feat/task4-hieu-health:

Bản chất Kỹ thuật: Active Database Probe (SELECT 1)

Không dùng ping tĩnh 200 OK. Hệ thống gửi truy vấn kiểm tra CSDL Postgres thực tế:

@Get()
async check(@Res() res: Response) {
  try {
    await this.prisma.$queryRaw`SELECT 1`;
    return res.status(HttpStatus.OK).json({ status: 'ok', database: { status: 'connected' } });
  } catch (err) {
    return res.status(HttpStatus.SERVICE_UNAVAILABLE).json({ status: 'degraded' });
  }
}

🎯 Bộ Câu hỏi Vấn đáp "Tủ" của Thầy Phiêu & Cách Trả lời

Câu 1: Tại sao Health Check của em lại gọi SELECT 1 xuống PostgreSQL mà không chỉ trả về chuỗi 200 tĩnh?

Trả lời: "Dạ thưa Thầy, nếu chỉ trả về 200 tĩnh thì endpoint đó chỉ báo tiến trình Node.js còn sống, hoàn toàn mù mờ trước tình trạng CSDL. Nếu kết nối CSDL bị đứt hoặc nghẽn connection pool, router vẫn điều phối khách vào container đó sẽ gây lỗi 500 sập dịch vụ. Việc chạy truy vấn nhẹ SELECT 1 là active probe kiểm tra thực tế kết nối DB, dùng làm căn cứ kích hoạt tự động Rollback trong pipeline CD khi triển khai container mới gặp sự cố ạ."

Câu 2: Tại sao em chọn saltRounds = 10 cho Bcrypt mà không chọn 15 hay 20?

Trả lời: "Dạ thưa Thầy, Bcrypt hoạt động theo hàm mũ 2^cost. Với saltRounds = 10, một phép băm mất khoảng ~70ms trên CPU máy chủ, là ngưỡng cân bằng vàng giữa an toàn mật mã chống tấn công vét cạn Brute-force và hiệu năng máy chủ. Nếu tăng lên 15 hay 20 thì mỗi lượt đăng nhập mất từ vài giây đến cả phút, gây nghẽn CPU (CPU Starvation) làm đơ server ạ."

Câu 3: Tại sao nhóm em chọn Monorepo mà không tách riêng 2 repo cho Web và API?

Trả lời: "Dạ thưa Thầy, theo bản ADR-002, mô hình Monorepo giúp cả 6 thành viên đồng bộ chung một chuẩn commit, chia sẻ chung DTO/Types giữa Client và Server, và chỉ cần 1 pipeline CI duy nhất trên GitHub Actions để kiểm thử tính tương thích giữa Web và API trước khi merge ạ."

Câu 4: Tường lửa phần cứng khác gì tường lửa phần mềm trong tài liệu triển khai của em?

Trả lời: "Dạ thưa Thầy, theo bài giảng 28/10 của Thầy, Tường lửa phần cứng là thiết bị vật lý chuyên dụng (Cisco/Fortigate) đặt trước cửa mạng, lọc gói tin bằng chip chuyên biệt theo Whitelist (chỉ mở cổng 443, chặn triệt để cổng 5432). Nó chịu tải cao và chống DDoS mà không tốn CPU/RAM của server; còn tường lửa phần mềm chỉ là lớp phòng thủ cục bộ thứ hai trên hệ điều hành ạ."

Câu 5: JWT có nhược điểm khó thu hồi tức thời (Token Revocation), em giải quyết thế nào?

Trả lời: "Dạ thưa Thầy, trong phạm vi MVP, em thiết lập thời hạn sống hợp lý 24h và lưu an toàn ở Client. Khi mở rộng thương mại, nhóm sẽ bổ sung cơ chế Refresh Token xoay vòng kèm Blacklist trên Redis để hủy token ngay lập tức khi đăng xuất ạ."

Câu 6: Tranh chấp tồn kho khi 2 khách cùng mua ly cà phê cuối cùng xử lý thế nào?

Trả lời: "Dạ thưa Thầy, nhóm em dùng Khóa lạc quan (Optimistic Locking) kết hợp Database Transaction (prisma.$transaction). Transaction nào đến trước trừ kho và tăng version thành công; transaction đến sau nhận diện kho thiếu sẽ Rollback và trả về lỗi 409 Conflict. Nhóm đã có bài test orders-concurrency.spec.ts bảo chứng ạ."

Câu 7: Chống trừ tiền trùng lặp khi mạng lag và khách bấm nút Thanh toán nhiều lần?
